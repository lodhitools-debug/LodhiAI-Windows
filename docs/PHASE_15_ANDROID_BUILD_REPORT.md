## 3. Cloud CI/CD Build Pipeline Implementation

To ensure Android compilation, unit testing, and APK artifact generation can execute autonomously without requiring manual software installation on the user's primary Windows PC, a dedicated cloud build workflow has been created:

- **Workflow File:** [`.github/workflows/android-build.yml`](file:///E:/LodhiAI-Windows/.github/workflows/android-build.yml)
- **Workflow Triggers:** Push to `main`/`master`, Pull Requests targeting `android/**`, and manual trigger via `workflow_dispatch`.
- **Cloud Runner Environment:** `ubuntu-latest`
- **Build Steps:**
  1. `actions/checkout@v4`: Checks out repository.
  2. `actions/setup-java@v4`: Configures Eclipse Temurin JDK 17 with Gradle caching.
  3. `gradle/actions/setup-gradle@v3`: Configures Gradle 8.7 runtime.
  4. `yes | sdkmanager --licenses || true`: Accepts Android SDK licenses automatically.
  5. `gradle testDebugUnitTest`: Executes native Android unit tests (`CompanionUnitTests.kt`).
  6. `gradle assembleDebug`: Compiles debug APK.
  7. `sha256sum app-debug.apk`: Calculates verifiable SHA-256 checksum of generated APK.
  8. `actions/upload-artifact@v4`: Publishes debug APK as downloadable GitHub Actions artifact (`lodhi-ai-android-companion-debug-apk`).
